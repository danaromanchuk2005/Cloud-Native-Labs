# Лабораторна робота 7. Безстатусна безпека: JWT-автентифікація, хешування паролів, протидія ін'єкціям та захист артефактів збірки у Node.js та Go

## 1. Мета роботи

Розширити багаторівневі сервіси з лабораторних робіт № 4–6 механізмами безстатусної безпеки (Stateless Security): впровадити автентифікацію та авторизацію на базі JSON Web Tokens (**JWT**), криптографічне хешування паролів за допомогою **bcrypt**, рольовий контроль доступу (**RBAC**), протидію SQL- та NoSQL-ін'єкціям, захисні HTTP-заголовки, обмеження частоти запитів (**Rate Limiting**), автентифікацію **WebSocket-з'єднань**, аудит подій безпеки у **MongoDB** та захист артефактів збірки (обфускація JS та стріпінг бінарника Go). Нова функціональність інтегрована через ланцюжок middleware-фільтрів без зміни бізнес-логіки рівня `Repository`.

## 3. Реалізація механізмів безпеки

### 3.1. Розширення схеми даних та криптографічне хешування паролів

* **Схема БД (`init.sql` / MongoDB):** до сутності `users` додано поля `password_hash VARCHAR(255) NOT NULL` та `role VARCHAR(20) NOT NULL DEFAULT 'user'`.
* **Хешування (`bcrypt`):** використовується алгоритм `bcrypt` із фактором складності $\text{cost} = 12$ (`SALT_ROUNDS = 12` у Node.js та `bcrypt.GenerateFromPassword(..., 12)` у Go). Сіль генерується криптографічно стійким генератором випадкових чисел автоматично.
* **Захист чутливих даних:** відкритий пароль ніде не зберігається; поле `password_hash` видаляється під час формування DTO у шарі `Service` і ніколи не потрапляє у HTTP-відповіді, логи чи WebSocket-повідомлення.

### 3.2. Безстатусна JWT-автентифікація та захист від `alg=none`

* **Пара токенів:**
  * `accessToken` — час життя $15$ хвилин, підписується ключем `JWT_SECRET`, містить claims `sub` (ID користувача), `role`, `iss`, `iat`, `exp`.
  * `refreshToken` — час життя $7$ днів, підписується окремим ключем `JWT_REFRESH_SECRET` і використовується на ендпоінті `POST /api/auth/refresh` для отримання нової пари токенів.
* **Захист від підробки та атаки `alg=none`:** під час верифікації явно вказується білий список алгоритмів (`algorithms: ['HS256']`), тому будь-який токен із модифікованим підписом або заголовком `"alg": "none"` відхиляється зі статусом `401 Unauthorized`.

### 3.3. Політика доступу (RBAC) та ланцюжок middleware

| Маршрут | Необхідний рівень доступу | Поведінка при порушенні |
| :--- | :--- | :--- |
| `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`, `GET /health` | Публічний (без токена) | `429 Too Many Requests` при перевищенні ліміту логінів |
| `GET /api/users`, `GET /api/users/:id`, `GET /api/events`, `GET /api/users/export` | `requireAuth` (ролі `user`, `admin`) | `401 Unauthorized` (відсутній або протермінований токен) |
| `POST /api/users`, `PUT /api/users/:id`, `DELETE /api/users/:id` | `requireAuth` + `requireRole('admin')` | `403 Forbidden` (якщо роль користувача `user`) |
| `WS /ws?token=<JWT>` | Валідний `accessToken` при handshake | `HTTP 401 Unauthorized` / WS close code `1008` |

### 3.4. Протидія ін'єкціям, Security-заголовки та Rate Limiting

* **SQL-ін'єкції:** усі SQL-запити виконуються виключно через параметризовані вирази (`$1, $2` у `pg` та `database/sql`), що унеможливлює виконання пейлоаду `'admin' --`.
* **NoSQL-ін'єкції:** middleware `sanitizeInputs` очищує ключі, що починаються зі знаку `$` (наприклад, `{"$gt": ""}`), а в репозиторії значення приводяться до примітивного типу `String()`.
* **Security Headers:** централізовано встановлюються заголовки:
  * `Content-Security-Policy: default-src 'self'; frame-ancestors 'none';`
  * `X-Frame-Options: DENY`
  * `X-Content-Type-Options: nosniff`
  * `Strict-Transport-Security: max-age=31536000; includeSubDomains`
  * `Referrer-Policy: no-referrer`
* **Rate Limiting:** для `POST /api/auth/login` налаштовано ліміт у $5$ спроб за $1$ хвилину з однієї IP-адреси; наступні запити блокуються зі статусом `429 Too Many Requests`.

### 3.5. Інтеграція з WebSocket Hub та MongoDB EventLogger

* **WebSocket Handshake:** під час події `upgrade` сервер витягує параметр `token` із URL (`ws://host/ws?token=<JWT>`), верифікує його та зберігає `(userId, role)` разом із підключенням у Hub. При реєстрації нового користувача всім авторизованим WS-клієнтам транслюється подія `user_registered`.
* **Аудит безпеки в MongoDB:** `EventLogger` записує події `user_registered`, `user_logged_in`, `login_failed` та `token_rejected` у колекцію `events` без збереження паролів, хешів або токенів.

## 4. Захист артефактів збірки та результати перевірки

### 4.1. Обфускація Node.js (`javascript-obfuscator`)

Вихідний код точки входу `src/server.js` оброблено утилітою `javascript-obfuscator` із увімкненим вирівнюванням потоку керування (`--control-flow-flattening`), ін'єкцією мертвого коду (`--dead-code-injection`), кодуванням рядків у Base64 (`--string-array-encoding base64`) та самозахистом (`--self-defending`):

```bash
npx javascript-obfuscator src/server.js \
  --output dist/app.js \
  --compact true \
  --control-flow-flattening true \
  --dead-code-injection true \
  --string-array true \
  --string-array-encoding base64 \
  --self-defending true
```

### 4.2. Стріпінг бінарного файлу Go (`-ldflags="-s -w" -trimpath`)

Виконуваний файл Go зібрано з видаленням таблиці символів (`-s`), відлагоджувальної інформації DWARF (`-w`) та шляхів файлової системи (`-trimpath`):

```bash
go build -ldflags="-s -w" -trimpath -o bin/app ./cmd/server
```

### 4.3. Порівняльна таблиця артефактів збірки

| Стек | Артефакт до захисту | Захищений артефакт | Розмір до / після | Характеристика артефакту |
| :--- | :--- | :--- | :--- | :--- |
| **Node.js** | `src/server.js` | `dist/app.js` | `374 B` $\rightarrow$ `4672 B` | Код стиснуто, рядки закодовано в Base64, ускладнено статичний аналіз |
| **Go** | Вихідний код (`./cmd/server`) | `bin/app` | `13 MB` (після стріпінгу) | `Mach-O 64-bit executable arm64`, видалено символи відлагодження та шляхи збірки |

### 4.4. Захист секретів у репозиторії

Файл `.env` із секретними ключами (`JWT_SECRET`, `JWT_REFRESH_SECRET`, паролі до PostgreSQL та MongoDB) додано до `.gitignore`. У Git-репозиторії збережено лише шаблон `.env.example` із порожніми значеннями змінних.

## 5. Висновки

1. **Безстатусна автентифікація та RBAC:** впровадження JWT (Access + Refresh токенів) та розділення повноважень на рівні middleware дозволило надійно захистити API без збереження стану сесій на сервері та без зміни бізнес-логіки репозиторіїв.
2. **Комплексний захист від типових атак:** поєднання `bcrypt` ($\text{cost} = 12$), параметризованих SQL-запитів, санітизації вхідних даних, перевірки `alg=HS256`, Rate Limiting та Security-заголовків закриває основні вразливості вебзастосунків (OWASP Top 10).
3. **Захист кінцевих артефактів:** обфускація JavaScript-коду та стріпінг бінарника Go ускладнюють реверс-інжиніринг і приховують службові шляхи середовища розробки перед розгортанням у хмарній інфраструктурі.

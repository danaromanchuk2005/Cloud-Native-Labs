# Лабораторна робота 1. Побудова базових HTTP-сервісів на Node.js та Go

## 1. Мета роботи
Ознайомитися з принципами побудови легковагових HTTP-мікросервісів у стилі REST на двох популярних для Cloud Native розробки платформах — **Node.js** (із використанням фреймворку `Express`) та **Go** (виключно засобами стандартної бібліотеки `net/http`). Реалізувати ідентичний CRUD-функціонал зі зберіганням стану в оперативній пам’яті (`in-memory storage`), передбачити ендпойнт перевірки працездатності `/health` та забезпечити повернення коректних HTTP-кодів стану.

## 3. Предметна область та модель даних

Як сутність для CRUD-операцій обрано **каталог книг (`Book`)**. Кожен об’єкт у сховищі має таку JSON-структуру:

```json
{
  "id": 1,
  "title": "Clean Architecture",
  "author": "Robert C. Martin",
  "year": 2017
}
```

* `id` (`integer`) — унікальний числовий ідентифікатор запису (генерується автоматично на сервері);
* `title` (`string`, обов’язкове поле) — назва книги;
* `author` (`string`, обов’язкове поле) — автор книги;
* `year` (`integer | null`, необов’язкове поле) — рік видання.

Обидва сервіси під час старту ініціалізують in-memory сховище двома тестовими записами (`id: 1` та `id: 2`). У реалізації на Go доступ до зрізу даних захищено за допомогою м’ютекса `sync.RWMutex` для безпечної конкурентної обробки запитів у горутинах.

## 4. Специфікація REST API

Обидва сервіси реалізують ідентичний контракт API:

| HTTP-метод | Ендпойнт | Призначення | Код успіху | Коди помилок |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/health` | Перевірка стану та доступності сервісу (Health Check) | `200 OK` | — |
| `GET` | `/books` | Отримання списку всіх книг | `200 OK` | — |
| `GET` | `/books/:id` | Отримання інформації про книгу за її `id` | `200 OK` | `400 Bad Request`, `404 Not Found` |
| `POST` | `/books` | Додавання нової книги до каталогу | `201 Created` | `400 Bad Request` |
| `PUT` | `/books/:id` | Повне оновлення даних існуючої книги за `id` | `200 OK` | `400 Bad Request`, `404 Not Found` |
| `DELETE` | `/books/:id` | Видалення книги за `id` | `204 No Content` | `400 Bad Request`, `404 Not Found` |

## 5. Інструкція із запуску

### 5.1. Запуск Node.js сервісу (порт `3000`)
```bash
cd lab1/node-service
npm install
node index.js
```
Сервер буде доступний за адресою: `http://localhost:3000`

### 5.2. Запуск Go сервісу (порт `8080`)
```bash
cd lab1/go-service
go run main.go
```
Сервер буде доступний за адресою: `http://localhost:8080`

## 6. Тестування працездатності (`curl`)

Нижче наведено приклади перевірки ендпойнтів (аналогічні запити виконуються для портів `3000` та `8080`):

1. **Перевірка статусу сервера (`/health`):**
   ```bash
   curl -i http://localhost:8080/health
   ```
   *Відповідь:* `HTTP/1.1 200 OK` та JSON `{"service":"go-books-service","status":"ok","timestamp":"..."}`.

2. **Отримання списку книг:**
   ```bash
   curl -i http://localhost:8080/books
   ```
   *Відповідь:* `HTTP/1.1 200 OK` та масив книг.

3. **Створення нової книги:**
   ```bash
   curl -i -X POST http://localhost:8080/books \
     -H "Content-Type: application/json" \
     -d '{"title": "The Phoenix Project", "author": "Gene Kim", "year": 2013}'
   ```
   *Відповідь:* `HTTP/1.1 201 Created` та створений об’єкт із `id: 3`.

4. **Оновлення запису:**
   ```bash
   curl -i -X PUT http://localhost:8080/books/3 \
     -H "Content-Type: application/json" \
     -d '{"title": "The Phoenix Project (Updated)", "author": "Gene Kim", "year": 2018}'
   ```
   *Відповідь:* `HTTP/1.1 200 OK` та оновлений об’єкт.

5. **Видалення запису:**
   ```bash
   curl -i -X DELETE http://localhost:8080/books/3
   ```
   *Відповідь:* `HTTP/1.1 204 No Content` (порожнє тіло відповіді).

6. **Перевірка валідації та обробки відсутніх ресурсів:**
   ```bash
   curl -i http://localhost:8080/books/999
   # -> HTTP/1.1 404 Not Found

   curl -i -X POST http://localhost:8080/books -H "Content-Type: application/json" -d '{}'
   # -> HTTP/1.1 400 Bad Request
   ```

## 7. Висновки
Під час виконання лабораторної роботи було розроблено два функціонально ідентичні HTTP-сервіси на **Node.js (`Express`)** та **Go (`net/http`)**:
* **Node.js + Express** дозволяє швидко описати маршрутизацію та серіалізацію JSON із мінімальним обсягом шаблонного коду завдяки однопотоковій подійно-орієнтованій моделі виконання.
* **Go + `net/http`** не потребує зовнішніх залежностей для побудови REST API, компілюється в один статичний бінарний файл і забезпечує високу продуктивність за рахунок горутин, проте вимагає явної синхронізації доступу до спільної пам’яті (`sync.RWMutex`).
* Наявність ендпойнту `/health` та стандартизованих HTTP-кодів відповіді робить обидва сервіси готовими до подальшої контейнеризації (Docker) та інтеграції з механізмами перевірки стану (`livenessProbe` / `readinessProbe`) в оркестраторах на кшталт Kubernetes.

## 1. Мета роботи

Побудувати комплексну систему спостережуваності (**Three Pillars of Observability**) для багатоконтейнерного мікросервісного застосунку в середовищі Docker Compose:
1. Налаштувати структуроване JSON-логування у `Node.js` (`pino`) та `Go` (`log/slog`) з автоматичним маскуванням чутливих даних (`redact`) і наскрізною кореляцією запитів за `reqId` та `trace_id`.
2. Реалізувати збір метрик у **Prometheus** (з `node-api`, `go-api` та `nginx-prometheus-exporter`) і візуалізацію чотирьох золотих сигналів (**Four Golden Signals**) та метрик безпеки у **Grafana**.
3. Впровадити розподілене трасування (**Distributed Tracing**) на базі **OpenTelemetry** та **Jaeger** з візуалізацією внутрішніх спанів застосунку й запитів до бази даних.
4. Провести навантажувальне тестування через HTTPS (`ApacheBench`) та порівняти продуктивність і ресурсоефективність сервісів на **Go** та **Node.js**.

## 3. Реалізація трьох стовпів спостережуваності (Observability)

### 3.1. Структуроване JSON-логування та захист конфіденційних даних (Logging)

Усі сервіси пишуть структуровані JSON-логи у `stdout`, що забезпечує єдиний формат аналізу подій і кореляцію між сервісами через ідентифікатори `reqId` та `trace_id`.

* **Node.js (`pino` + `redact`):** автоматично приховує заголовки `authorization` та поле `password` у тілі HTTP-запитів, замінюючи їх значення на `"[REDACTED]"`:
  ```json
  {"level":"INFO","time":"2026-11-15T21:39:06.597Z","service":"node-api","replica":"91c0abd378c4","pid":18,"reqId":"3fa7f791-c8b2-496c-a922-b31ed9b989b2","trace_id":"4ac5c06939fc99aea2da7fa366e9bffb","method":"POST","url":"/api/auth/login","headers":{"authorization":"[REDACTED]"},"body":{"email":"bohdana@test.local","password":"[REDACTED]"},"msg":"request in"}
  ```
* **Go (`log/slog`):** фіксує кожен вхідний запит із точним часом виконання `durationMs`, ідентифікатором репліки та `trace_id`:
  ```json
  {"time":"2026-11-15T21:39:06.585764295Z","level":"INFO","msg":"request completed","service":"go-api","replica":"aba34de98bd0","reqId":"8ab25167466681ea","trace_id":"4338abf74c0f29453c9d5634d05568ce","method":"GET","url":"/api/reports","status":200,"durationMs":0.274,"client_ip":"192.168.65.1"}
  ```

### 3.2. Збір метрик у Prometheus та дашборд Grafana (Metrics)

Перевірка через Prometheus API (`/api/v1/targets`) підтвердила активний стан (`up`) усіх 5 цілей збору метрик:
* `go-api` (`go-app:8080`) — `up`
* `nginx` (`nginx-exporter:9113`) — `up`
* `node-api` (`node-app-1:3000`, `node-app-2:3000`, `node-app-3:3000`) — `up`

На дашборді Grafana **«Lab 9 — Four Golden Signals & Security Metrics»** реалізовано 6 панелей:
1. **Traffic — RPS by Service (Node.js vs Go):** відображає інтенсивність вхідного трафіку в розрізі сервісів (пік ~35 RPS під час серії бенчмарків).
2. **Errors — 5xx Error Rate (%):** контролює частку серверних помилок (`0%` протягом усього тестування).
3. **Latency — p50 / p95 / p99 (seconds):** відстежує медіанну та хвостові затримки внутрішньої обробки запитів (`2.5–5 ms`).
4. **Saturation — Node Event Loop Lag (s) & Go Goroutines:** демонструє завантаженість рантаймів — стабільні ~11–13 горутин у Go у стані спокою з короткочасним піком до ~42 горутин під навантаженням та мінімальний Event Loop Lag (`< 1 ms`) у Node.js.
5. **Security — Auth Failures (401/403 RPS):** фіксує сплески помилок автентифікації після серії запитів із невірним паролем (`HTTP 401`).
6. **Security — Nginx Active & Dropped Connections (Rate Limit):** показує піки активних з'єднань (~35 одночасних з'єднань) під час навантажувального тестування.

### 3.3. Розподілене трасування OpenTelemetry та Jaeger (Tracing)

Інструментація OpenTelemetry передає спани з обох мікросервісів у Jaeger:
* **Go (`go-api`):** для запиту `GET /api/reports` (`trace_id: 4338abf74c0f29453c9d5634d05568ce`, тривалість `385 µs`) зафіксовано кореневий HTTP-спан та вкладений кастомний спан бізнес-логіки `reports.generate` (`170 µs`).
* **Node.js (`node-api`):** для запиту `GET /api/users` (`trace_id: 193035f`, загальна тривалість **20.96 ms**, глибина **5**, **13 спанів**) деталізовано час виконання кожного етапу:
  * Express middleware (`query` — `247 µs`, `jsonParser` — `104 µs`, `metricsMiddleware` — `395 µs`, JWT middleware — `1.1 ms`);
  * бізнес-обробник `users.list` (`12.52 ms`), включаючи підключення до пулу PostgreSQL (`pg-pool.connect` `8.52 ms`, `tcp.connect` `983 µs`, `dns.lookup` `522 µs`) та виконання SQL-запиту `SELECT` до БД `appdb` (`2.82 ms`).

## 6. Виявлені та усунені технічні проблеми (Troubleshooting)

1. **Невідповідність залежностей при збірці Go (`go: updates to go.mod needed`):** перед збіркою `go-service/Dockerfile` виконано `go mod tidy` у каталозі `go-service`, що синхронізувало `go.mod` і `go.sum`.
2. **Конфлікт портів `80` та `443` на хості:** зупинено контейнер `lab8-nginx-1` із попередньої лабораторної роботи, який займав зовнішні порти.
3. **Попередження змінних оточення PostgreSQL у Docker Compose:** у файл `.env` додано `POSTGRES_USER`, `POSTGRES_PASSWORD` та `POSTGRES_DB`.
4. **Помилка генерації JWT при логіні (`"algorithms" is not allowed in "options"`):** у файлі `node-service/src/service/userService.js` параметр `algorithms: ['HS256']` у виклику `jwt.sign()` виправлено на `algorithm: 'HS256'`.
